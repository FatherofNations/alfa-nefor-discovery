# Правила проекта

Интерактивный прототип по Figma-макетам. Стек: Next.js 15 (App Router), React 19,
глобальный CSS. Порт — 3001 (3000 занят чужим проектом). Работа с макетом — через
Figma MCP (файл `HL4PatufFZkyPKtx3LGivP`), эталоны и design context кешируются в `.figma/`.

## Иконки: только SVG нужного цветового варианта из Figma

Интерфейсные иконки никогда не raster (никаких PNG/WebP для иконок — только растр
для иллюстраций, аватаров, фото и брендовых артов). Правильный вариант берём так:

1. **Не брать глиф из общего design context компонента.** Контекст библиотечного
   компонента (кнопка, filter-tag, addon и т.п.) отдаёт дефолтный вариант глифа —
   часто это акцентный цвет (`#0024E1`) или плейсхолдер, а не тот цвет, что в макете.
2. **Вызывать `get_design_context` на конкретном инстансе во фрейме** (id из
   `get_metadata` корневого узла), с `disableCodeConnect: true`. В ответе
   `const assetPathPrefix` + константы ассетов — это варианты именно этого инстанса.
3. **Использовать ассет, который реально рендерится в коде ответа** — обычно
   `imgFixer` (глиф, подставленный в слот). Остальные `img*` — соседние варианты
   компонента; скачивать их смысл есть только чтобы сверить цвет.
4. **Сверить цвет с эталоном** (`.figma/main/reference-full.png`, crop через `sips`)
   до подключения. У глифов Альфы фиксированные заливки: `#030306` (primary),
   `#747474` (secondary), `#CCCCCC`/`#DCDCdd` (tertiary), `#0024E1` (accent),
   white для тёмных кнопок. Если в макете иконка на тёмном фоне — брать белый
   вариант (у support-кнопки он лежит отдельным ассетом рядом с фиолетовым).
5. **IconView-иконки (балансы, аватары, знаки)** собираются из трёх частей:
   маска-фигура (`imgShapeContent`, используется как CSS mask, её цвет не важен),
   сплошная заливка `BgColor`/`BgImg` (цвет/фото берутся с узла конкретного
   инстанса: `get_design_context` на `<node>;448:17360` / `...;448:17392` —
   иначе придёт плейсхолдер) и глиф по центру (`imgFixer`).
6. Скачанные SVG кладём в `public/assets/figma/` под семантическими именами
   (`filter-icon.svg`, `mail-icon.svg`), ссылкаем напрямую. Корневые width/height
   в SVG не трогаем, размеры задаём обёрткой.

## Состояния и контент

Не придумывать элементы, данные и состояния, которых нет в переданном макете:
никаких toast, выдуманных ответов ассистента, дополнительных пунктов меню или
операций. Интерактив только на контролах, оправданных макетом (табы, дропдаун
«Дела в работе», поиск по существующим операциям, чекбоксы, сдвиг карусели).

## Вёрстка

- Тени (drop-shadow) рвутся об `overflow: hidden`. Глобально стоит
  `box-sizing: border-box` — padding вьюпорту не помогает (клип идёт по border box);
  давайте тени место через реальную высоту + компенсирующий отрицательный margin
  (см. `.tasks-viewport`: высота 240 = 212 контента + 28 на тень, `margin-bottom: -28`).

## Проверки после правок

- `npm run lint` (должен быть чистым, `--max-warnings 0`).
- `npm run verify http://localhost:3001` — сервер должен быть запущен.
- Скриншот 1600×900 headless Chrome и parity против `.figma/main/reference-full.png`.
- Не запускать `next build` при живом `next dev` (общий `.next`).
